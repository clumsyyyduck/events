# Верификация организаторов без хранения паспортных данных

Дата исследования: 2026-10-20. Контекст: маркетплейс событий (Москва/СПб), вход по номеру телефона. Нужно убедиться, что организатор — реальный идентифицированный человек, но не хранить у себя паспорт/документы.

Пометка **«не подтверждено»** — факт не удалось сверить с официальным источником; перед решением уточнить у провайдера.

## 1. Госуслуги / ЕСИА («Вход через Госуслуги»)

**Какие данные получаем.**
- ЕСИА отдаёт данные о физлице по scope (например `fullname`, `birthdate`, `id_doc`, `email`, `mobile`, `contacts`); запрашиваемые атрибуты нужно обосновать в заявке. Документы (`id_doc`) — отдельный scope, его можно не запрашивать.
- В данных о физлице есть атрибут **`trusted` — «Подтверждена ли УЗ» (true/false)**. Это ровно нужный нам флаг «реальный человек, личность подтверждена». Источник: Методические рекомендации по использованию ЕСИА, версия 3.40 (2023), раздел о ресурсе `prns`, пример ответа и таблица атрибутов — копия PDF: https://ebs.ru/upload/iblock/ff7/k3ac8tyuztmspx9fapdytyd0pd40fyx8/metodicheskierekomendatsiipoispolzovaniyuesiav340.pdf
- То есть технически можно запросить только `openid` + `fullname` (или даже без ФИО) и проверить `trusted=true`.

**Требования к подключению.**
- ПП РФ от 10.07.2013 № 584: сведения из ЕСИА предоставляются «иным организациям, индивидуальным предпринимателям… в случаях, установленных федеральными законами» и актами Правительства / решениями президиума Правкомиссии. Т.е. **просто по желанию коммерческая компания подключиться не может** — нужно нормативное основание. https://legalacts.ru/doc/postanovlenie-pravitelstva-rf-ot-10072013-n-584/
- Регламент информационного взаимодействия (v2.23): в заявке на подключение указываются «нормативные основания для подключения ИС (ссылка на пункт правового акта)», обоснование перечня атрибутов; решение о подключении принимает Минцифры. https://rulaws.ru/acts/Reglament-informatsionnogo-vzaimodeystviya-Uchastnikov-s-Operatorom-ESIA-i-Operatorom-ekspluatatsii-infr-solt-bubiiejd/
- Процедура: подтверждённая УЗ руководителя, КЭП руководителя, регистрация организации в ЕСИА, регистрация ИС в СМЭВ, Технологический портал, заявки на тестовую и продуктивную среду, сертификат ЭП ИС. https://info.gosuslugi.ru/articles/Как_подключиться_к_ЕСИА/
- Криптография: подпись запросов по ГОСТ Р 34.10-2012 / 34.11-2012 сертифицированными российскими СКЗИ (Метод. рекомендации v3.40, см. выше). ПП №453 п.4 также требует российские криптоалгоритмы с 01.01.2022.
- С 01.01.2027 ужесточаются требования к подключениям (оценка влияния на СКЗИ, проверка реализации OIDC в ФСБ, защита канала; переходный период до 31.12.2026) — **не подтверждено** по первоисточнику, только пресс-релиз: https://companies.rbc.ru/news/4Zd8jkVwEJ/napominaem-o-novyih-trebovaniyah-k-rabote-s-esia/
- Стоимость: официально платы за подключение не нашли — **не подтверждено**; реальные расходы — КЭП, СКЗИ (КриптоПро и т.п.), разработка/интегратор.

**Путь для коммерческой площадки — эксперимент ПП РФ от 27.03.2021 № 453.** Эксперимент по идентификации через ЕСИА пользователей соцсетей, потребителей и продавцов (исполнителей) на сайтах, где можно ознакомиться с предложением о сделке, агрегаторов, сервисов поиска работы. Владельцы ресурсов участвуют добровольно **по согласованию с Минцифры**. Срок в действующей редакции — до 31.12.2026; Минцифры подготовило проект продления до 2030 (не принят на дату исследования).
- Текст: https://base.garant.ru/400544050/ , https://www.consultant.ru/document/cons_doc_LAW_381406/
- Продление: https://www.garant.ru/news/2245856/
- Участники — крупные площадки (Ozon, Авито, Wildberries, hh.ru — 13 платформ): https://ppt.ru/news/gosudarstvennye-uslugi/vkhod-cherez-gosuslugi-na-marketpleysakh-predlagayut-prodlit-do-2030-goda (вторичный источник)
- Критерии отбора участников и порядок заявки в тексте положения найти не удалось — **не подтверждено**. Фактически участвуют только крупные игроки.

**Реалистичность для стартапа:** низкая на MVP. Нужно юрлицо, КЭП, СКЗИ, согласование Минцифры, эксперимент может закончиться 31.12.2026. Вернуться, когда будет юрлицо и аудитория.

## 2. Банковские ID

### Т-Банк T-ID — лучший кандидат
- **Флаг без документов есть.** Метод `GET /api/v1/individual/identification/status` (scope `opensme/individual/identification/status/get`): «Метод возвращает информацию о том, идентифицирован ли пользователь», нужно согласие пользователя. https://developer.tbank.ru/docs/api/get-api-v-1-individual-identification-status
- **ФИО и телефон** — через `POST https://id.tbank.ru/userinfo/userinfo`, scope `profile` и `phone`; «Доступно только для партнерской интеграции»; `client_id`/`client_secret` выдаются «после подписания договора». https://developer.tbank.ru/docs/api/t-id-informatsiya-o-polzovatele
- Паспорт — **отдельный** метод и scope (`opensme/individual/passport/get`), его можно не запрашивать. https://developer.tbank.ru/docs/api/get-api-v-2-passport
- Также есть метод «Получить информацию о статусе самозанятого» (в том же разделе T-ID).
- «Делегированная идентификация» (передача ФИО, паспорта, адреса по 115-ФЗ) — для субъектов 115-ФЗ; нам не нужна. https://developer.tbank.ru/docs/products/TID/delegate-identification
- Требования: договор с Т-Банком, партнёр — организация. Нужен ли расчётный счёт в Т-Банке, ИП или только ООО — **не подтверждено**. Стоимость — индивидуально, через менеджера/почту (страница tbank.ru/software/t-id/documentation, недоступна для автоматической загрузки) — **не подтверждено**.
- Ограничение: работает только для клиентов Т-Банка, прошедших идентификацию.

### Сбер ID
- Scope разбиты на пакеты: Light (`openid`, `email`, `mobile`), Standart (`name` — ФИО, `birthdate`, `gender`), Professional (`maindoc` — паспорт, `inn`, `snils`, … и **`is_self_employed`** — признак самозанятого). https://developers.sber.ru/docs/ru/sberid/service/scopes
- **Отдельного флага «личность подтверждена» в списке scope нет.** Данные берутся из профиля клиента банка («верифицированные данные пользователя»), т.е. ФИО из Сбер ID фактически подтверждено банком — но это наш вывод, явной формулировки-флага нет.
- Подключение: регистрация организации на портале, оферта по ЭДО, выдают Client ID / Secret / сертификат; «Сервис предоставляется бесплатно для пользователей и наших партнеров». https://developers.sber.ru/docs/ru/sberid/guidebook/overview
- Сертификат — вероятно mTLS (**не подтверждено**). Условия доступа к пакету Professional — **не подтверждено**.

### Альфа ID
- Вход на сайт партнёра с автозаполнением анкеты, согласие на передачу данных. https://alfabank.ru/everyday/alfa-id/
- Пример: Авито через Alfa ID даёт бейдж «Документы проверены» (вторичный источник): https://www.comnews.ru/content/233296/2024-05-22/2024-w21/1010/podtverdit-profil-avito-teper-mozhno-pomoschyu-alfa-id
- Публичной документации для разработчиков, состава данных, флага идентификации и условий подключения не нашли — **не подтверждено**.

### ВТБ ID
- Есть страница интеграции для бизнеса; client_id выдаётся при регистрации приложения партнёра; банк не передаёт финансовую информацию. https://www.vtb.ru/malyj-biznes/vtb-id/integraciya/ (страница не открылась при проверке; данные по выдаче поиска)
- Состав данных, флаг, стоимость — **не подтверждено**.

## 3. VK ID
- Scope: `vkid.personal_info` (фамилия, имя, пол, фото, дата рождения), `email`, `phone`. https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes
- Поле **`verified`** в ответе — это «синяя галочка рядом с именем пользователя, которая выдается известным личностям» — **не** подтверждение личности. https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/api-description
- Серая галочка «данные подтверждены» (через Госуслуги, Сбер ID, T-ID, Alfa ID, ВТБ ID) существует внутри VK (https://kod.ru/vk-verification-with-gosuslugi), но передаётся ли этот признак партнёрам — **не подтверждено** (в API-документации не найден).
- Подключение: нужен верифицированный профиль бизнеса в VK Бизнес ID, иначе приложения блокируются. https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/verification
- **Вывод:** удобный вход, но задачу «реальный человек» не решает.

## 4. Единая биометрическая система (ЕБС)
- 572-ФЗ: идентификация (ст. 9) и аутентификация (ст. 10) через ЕБС — госорганы, ЦБ, финорганизации, «иные организации, ИП… в случаях, установленных федеральными законами, актами Правительства». Требования к организации (ст. 10 ч. 7): не в перечнях по экстремизму/терроризму, нет судимости у руководителя, нет записи о недостоверности в ЕГРЮЛ. https://rg.ru/documents/2023/01/09/document-identifikaciya.html
- Хранить биометрию вне ЕБС запрещено; коммерческая биометрия — через аккредитованные Минцифры организации. Порог уставного капитала 500 млн ₽ для аккредитации — **не подтверждено** (только вторичный источник).
- **Вывод:** для маркетплейса событий нет правового основания и смысла. Не вариант.

## 5. KYC платёжного провайдера
- **ЮKassa «Безопасная сделка»** для платформ частных продавцов: позволяет «проводить сделки без идентификации пользователей», выплаты на карты/кошельки ЮMoney с лимитами. То есть ЮKassa **не** даст флаг «продавец идентифицирован». https://yookassa.ru/developers/solutions-for-platforms/safe-deal/basics
- **ЮKassa Выплаты**: выплаты физлицам на карту/ЮMoney/СБП; для СБП есть проверка, что «получатель перевода и владелец платежного средства — это один и тот же человек» (это проверка ФИО по номеру, не KYC). https://yookassa.ru/developers/payouts/overview
- ЮKassa **прекратила поддержку сервисов для самозанятых с 29.12.2025** (включая выплаты самозанятым). https://yookassa.ru/developers/payouts/scenario-extensions/self-employed
- **Т-Банк, номинальный счёт**: платформа сама создаёт бенефициара (`POST /api/v1/nominal-accounts/beneficiaries`) и для физлица передаёт **паспортные данные**; банк проверяет бенефициара в финмониторинге («Получить результаты проверки бенефициаров в финансовом мониторинге»). https://developer.tbank.ru/docs/products/nominal , https://developer.tbank.ru/docs/api/post-api-v-1-nominal-accounts-beneficiaries — т.е. паспорт проходит через нас (обработка ПДн), даже если мы его не храним.
- **Т-Банк, выплаты самозанятым**: добавление самозанятых по реквизитам, реестры, чеки; при отсутствии карты Т-Банка банк выпускает её. https://developer.tbank.ru/docs/products/self-employed — если самозанятый становится клиентом банка, банк его идентифицирует, но отдельного «флага» для платформы в этой схеме не нашли — **не подтверждено**.
- **Вывод:** выплаты провайдера частично проверяют организатора (карта/счёт на его имя, финмониторинг), но готового «verified: yes» обычно нет, а в схемах с номинальным счётом мы сами передаём паспорт. Детали — в `docs/research/payments.md`.

## 6. ФНС: проверка статуса самозанятого (НПД) по ИНН
- Официальный API: `POST https://statusnpd.nalog.ru/api/v1/tracker/taxpayer_status`, тело `{"inn": "...", "requestDate": "YYYY-MM-DD"}`, ответ `{"status": true, "message": "... является плательщиком налога на профессиональный доход"}`. Лимит — не чаще 2 запросов в минуту с одного IP. Бесплатно, без договора. Описание API (PDF ФНС): https://npd.nalog.ru/html/sites/www.npd.nalog.ru/api_statusnpd_nalog_ru.pdf , форма: https://npd.nalog.ru/check-status/
- **Что доказывает:** только то, что этот ИНН на дату — плательщик НПД. **ФИО не возвращается**, поэтому сервис не доказывает, что ИНН принадлежит именно нашему пользователю (можно ввести чужой ИНН).
- Для ИП/ООО аналогично можно проверить запись в ЕГРЮЛ/ЕГРИП (egrul.nalog.ru) — то же ограничение: подтверждается существование лица, а не связь с аккаунтом.
- Полезно как дополнительная проверка в связке с T-ID/Сбер ID (сверить ИНН/ФИО) или для чеков при выплатах.

## 7. Что остаётся по 152-ФЗ в любом случае

Мы уже оператор ПДн (храним телефоны). Получение ФИО или даже только флага, привязанного к аккаунту, — тоже обработка ПДн. Независимо от выбранного варианта:

- **Уведомление Роскомнадзора** до начала обработки (ст. 22 152-ФЗ), с целями, категориями данных и правовыми основаниями; при добавлении ФИО/ИНН — обновить сведения. Форма — приказ РКН от 28.10.2022 № 180. Закон: https://www.consultant.ru/document/cons_doc_LAW_61801/
- **Согласие** конкретное, информированное и **оформленное отдельно от иных документов** (ст. 9 ч. 1, действующая редакция) — не «галочка» внутри оферты. https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/ . Плюс отдельное согласие пользователя в интерфейсе банка/ЕСИА на передачу данных нам.
- **Политика обработки ПДн**, опубликованная на сайте (ст. 18.1).
- **Локализация**: запись, хранение и т.п. ПДн граждан РФ — в базах на территории РФ (ст. 18 ч. 5) — хостинг в РФ.
- **Меры защиты** (ст. 19), ответственный за ПДн, учёт инцидентов и уведомление РКН об утечке (ст. 21).
- **Минимизация**: если запрашивать только флаг + ФИО (без паспорта), растёт простота и снижается риск; штрафы за утечки и неуведомление выросли с 30.05.2025 (вторичный источник: https://ppt.ru/art/personal-data/shtraf-za-nepodachu-uvedomleniya-ob-obrabotke-personalnykh-dannykh — точные суммы **не подтверждено** по КоАП).

## Рекомендация для MVP

1. **Основной путь — T-ID (Т-Банк):** запрашивать только `profile` (ФИО) + метод `identification/status`. Храним у себя: `sub` T-ID, ФИО, `verified_by = tbank`, `verified_at`. Паспорт не запрашиваем. Нужен договор — значит, нужно ИП/ООО; уточнить у Т-Банка стоимость и обязателен ли расчётный счёт.
2. **Второй провайдер — Сбер ID** (бесплатно, самая большая база): пакет Standart (ФИО). Явного флага нет — уточнить у support_sberid@sber.ru, считаются ли данные Standart подтверждёнными банком.
3. **Дополнительно — ФНС НПД по ИНН** для организаторов-самозанятых (бесплатно, без договора): сверять с ИНН/признаком самозанятого из банковского ID.
4. **ЕСИА и ЕБС — не на MVP.** ЕСИА держать в планах: следить за продлением эксперимента ПП №453 до 2030 и подать заявку в Минцифры, когда будет юрлицо и объём.
5. **Пока нет юрлица/договоров** — ручная модерация организатора + проверка статуса НПД/ЕГРИП, без загрузки сканов паспорта.
6. Параллельно привести в порядок 152-ФЗ (уведомление РКН, отдельное согласие, политика, хостинг в РФ) — это нужно уже из-за телефонов.
