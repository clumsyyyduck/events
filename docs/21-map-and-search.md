# Карта, фильтры и поиск

> Статус: черновик. Пока описана только нагрузка: как карта и фильтры работают при большом числе событий.

## Исходные условия

- Несколько городов-миллионников, в каждом — до **1 000 000 событий** (закладываемся на такой масштаб, даже если на старте их будут сотни).
- Большая часть из них — **архив** (прошедшие события, нужны для отзывов и профиля организатора). Для карты и фильтров важны только **актуальные**: опубликованные и ещё не прошедшие.
- Пользователь видит одновременно небольшой участок карты и короткий список.

## Главный принцип

**Приложение никогда не загружает все события.** Каждый экран запрашивает у сервера только то, что показывает:

| Что на экране | Что запрашиваем | Объём ответа |
|---|---|---|
| Метки на карте | События в видимой области карты, с фильтрами | Не больше ~300 меток; при большем числе — группы |
| Группы меток (кластеры) | Сервер сам объединяет близкие события в группы с числом | Десятки групп |
| Список | Первая страница событий в видимой области | 20 штук, дальше — подгрузка при прокрутке |
| Числа в окне категорий | Только числа по каждому виду | ~70 чисел |
| Кнопка «Показать N событий» | Одно число | 1 число |

## Как считать числа в фильтрах

Числа не пересчитываются «вручную» перебором миллиона событий при каждом нажатии.

1. **Числа по видам в городе** («Волейбол — 1 240») — заранее посчитанные счётчики. Обновляются при публикации, отмене и окончании события и хранятся в быстром кэше. Запрос занимает миллисекунды при любом числе событий.
2. **Число с комбинацией фильтров** («Волейбол + выходные + до 1000 ₽ + метро Сокол») — запрос к поисковому движку. Подсчёт по нескольким фильтрам сразу (фасеты) — его основная задача, на миллионах записей это десятки миллисекунд.
3. **Приблизительные числа.** Больше 1000 можно показывать округлённо: «1 000+», «10 000+». Точное число пользователю не нужно, а считать его дороже.
4. **Запрос не на каждый клик.** Число обновляется через 300 мс после последнего изменения в окне фильтров, а не на каждое нажатие галочки.

## Карта при большом числе событий

- **Кластеризация на сервере.** На мелком масштабе (весь город) сервер возвращает не 50 000 меток, а сетку групп: «🟠 320» в каждом районе. Чем ближе масштаб, тем мельче группы, на уровне улиц — отдельные метки.
- **Запрос по области.** Карта отправляет координаты видимого прямоугольника, масштаб и фильтры. При перемещении карты — новый запрос с задержкой ~200 мс после остановки.
- **Кэш на сетку.** Ответы для одинаковых квадратов карты и фильтров кэшируются на 1–2 минуты: многие пользователи смотрят центр города с одинаковыми фильтрами.

## Этапы

| Этап | Решение | Когда менять |
|---|---|---|
| MVP | Одна база (PostgreSQL + PostGIS для координат). Индексы по городу, дате, виду и координатам. Числа — SQL-запросами с кэшем | Пока актуальных событий в городе до ~100 000 и запросы укладываются в 200 мс |
| Рост | Отдельный поисковый движок для фильтров, чисел и поиска по тексту (OpenSearch, Typesense или аналог). База остаётся источником правды | Когда фильтры или поиск начинают тормозить |
| Масштаб | Готовые слои карты (векторные тайлы) с кластерами, раздельные серверы под города | Десятки городов, сотни тысяч пользователей одновременно |

Выбор конкретных технологий — в `31-tech-stack.md`.
